# HANDOFF.md — Template

Copy to project root. Rewrite at the end of every work session.

A handoff exists for one reason: the next agent has no memory of this one. Write for a
reader who is competent, well-intentioned, and completely uninformed.

**The stale-file problem is the reason this file exists.** Every other file in the project
says what is true. This one says what is true *now*, and which of the others to trust.
Without it, the next agent reads an old status file and quietly rebuilds on sand.

---

## 1. One-paragraph state

What this project is, where it stands, and what happens next. If the reader stops here,
they should still know enough not to do damage.

## 2. Authority order

1. The user's words.
2. Project locked documents (list them by path).
3. Kit laws.
4. Kit canon spine.
5. Earlier projects — craft only, never canon.

## 3. Edge

The exact position. Chapter number, rank, soul power, age, rings held, skills held.
What has *not* happened yet. Never vague.

**Say which file wins when two disagree.** This is the whole point of the section.

## 6. Open questions

What is undecided, and what each option would cost. Never hide uncertainty here; the next
agent will otherwise invent an answer and believe it.

## 7. Known gaps

Things that are known-wrong or known-incomplete and deliberately not yet fixed.

## Writing rules

- Never write "as previously discussed." There is no previously.
- Never write "recently." Give the date.
- If you are unsure whether something is still true, mark it `[unverified]`.
- Shorter is better. A handoff nobody reads protects nothing.
