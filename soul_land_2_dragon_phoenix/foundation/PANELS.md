# Status and panel policy

The machine-readable checkpoint is [CURRENT_STATE.json](../state/CURRENT_STATE.json).
[STATUS.md](../STATUS.md) is a generated author/agent view. Neither is a window
inside Jingheng’s mind, a guiding system or a source of free information.

No in-prose power terminal is adopted. A relevant rank test, tool measurement or
observed training result can appear naturally in a scene; a repeated inventory
of all souls, rings, techniques and ancestors cannot replace action.

Undetermined opening values are null. Do not display them as rank zero, zero
rings, no equipment, perfect mastery or a hidden divine stage. A proposed rank
band in an analysis is not the current panel. Two martial souls do not create
two additive cultivation bars.

A future reader-facing summary must be permitted by the author’s style and
contain only established information. It must distinguish an owned device from
a design, technical ability from certification, a learned skill from a ring gift,
and a burst feat from sustainable output. Changes belong in the actual event
ledger before they appear in a new summary.

If a presentation changes, keep one canonical state owner and regenerate views.
Do not maintain a new STATUS_PANEL.md with independent numbers merely to imitate
another serial’s directory. A link to the true owner is safer than a second panel.

## Preflight checkpoint view
