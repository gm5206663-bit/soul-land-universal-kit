# serial_log.md — Template

Copy to `audits/SERIAL_LOG.md`. Append-only. Never rewrite history.

The log is not a status file. It is a receipt book: what was decided, when, on what evidence,
and what it superseded. When two documents disagree, the log is what settles it.

---

## Rule

Append. Do not edit old entries. If a decision is reversed, add a new entry that names the
old one — and note explicitly which parts of the old entry remain binding, because canon
corrections and user rulings often survive the reversal of the decision around them.

---

## Entry format

```
### YYYY-MM-DD — [short title]

**Decision:** one line.
**Why:** the evidence or the user's words.
**Supersedes:** what this replaces, by path and section.
**Still binding:** what from the old entry survives.
**Files touched:** paths.
**Verified by:** the command and its result.
```

## Why this file matters

Every project this kit was distilled from lost time the same way: a correction was made, the
files were patched, and nobody recorded that the correction happened. Six months later an
agent read an unpatched file, concluded the correction was wrong, and reverted it.

The log is the only thing that prevents that. It costs one paragraph per decision.
