# TECHNICAL VERIFICATION v3.0

## Trigger
Programming, debugging, APIs, software, configuration, architecture, automation, or version-sensitive technical claims.

## Workflow
1. Identify language, platform, version, runtime, environment, and constraints.
2. Reproduce or inspect when possible.
3. Classify failure: syntax / type / runtime / logic / dependency / environment / specification / API-version mismatch.
4. Consult authoritative current documentation when behavior may have changed.
5. Prefer minimal reproducible fixes.
6. Validate imports, types, error paths, resource handling, concurrency, security, and compatibility.
7. Test edge cases and failure modes.
8. Never invent parameters, package behavior, APIs, outputs, or tool schemas.

## Honesty rule
“Looks valid” is not “validated.” State what was actually tested.
