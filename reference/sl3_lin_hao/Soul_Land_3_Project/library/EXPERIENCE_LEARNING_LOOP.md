# EXPERIENCE LEARNING LOOP v3.0

## Purpose
Turn repeated failures and successful corrections into reusable preventive controls without treating every old detail as a permanent truth.

## Experience classes
- FAILURE_PATTERN: recurring mechanism that caused an error
- SUCCESS_PATTERN: workflow that repeatedly improved outcomes
- PROJECT_RULE: applies only to a named project/universe
- USER_PREFERENCE: applies when relevant and not overridden
- TOOL_LIMITATION: known constraint of an available tool
- TEMPORAL_FACT: expires or may change

## Historical failure catalog for this workflow
Common recurring failures observed in prior work include:
1. rushing into prose before reconstructing state
2. relying on memory instead of verifying canon/current facts
3. using future canon knowledge as character knowledge
4. mixing facts from separate fictional universes or AUs
5. accidentally changing canon event order
6. inventing travel/location transitions
7. inconsistent ages, dates, or chronology
8. treating strong characters as artificially weak to manufacture tension
9. inflating an OC's power without earned foundation
10. treating Adaptation as universally improving everything
11. forgetting consequences of an earlier divergence
12. copying an earlier correction only at the sentence level, leaving the dependency chain wrong
13. choosing a plausible source instead of the authoritative source
14. treating search snippets or tool output as proof without inspecting evidence
15. overconfidently filling gaps where the evidence is genuinely missing
16. answering too quickly when the task required deep verification
17. confusing similar entities, versions, remakes, editions, products, or people
18. failing to distinguish event date from publication date
19. using a tool because it exists rather than because it materially helps
20. producing an artifact without checking its actual file/content state

## Preventive use
Before a similar task, identify which failure modes apply and attach the corresponding control.

## Non-contamination rule
Historical experience teaches process, not facts. A prior story fact must not become a universal rule unless explicitly designated as one.

## Learning rule
Only preserve a lesson that is generalizable. Preserve project-specific details separately.
