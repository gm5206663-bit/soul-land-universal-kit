# Supergirl — the re-acceptance, prepared and proved

**Author's ruling, 2026-10-30:** *re-accept the repaired chapters.*

This directory holds the change that closes the one red gate on the account, **tested to green
against Supergirl's own gate before it was filed** — not proposed on the strength of reading the
validator.

---

## What is actually broken

`tools/run_all.py` → `STRUCTURE: FAIL`, seven `ACCEPTED_HASH` errors, chapters 9–15.

Read `tools/verify.py:111` and the failure is one line of arithmetic:

```python
if not p.is_file() or sha(p) != c.get('sha256'):
    errors.append('ACCEPTED_HASH: missing or changed chapter ' + rel)
```

The manifest holds the hash of the file the author accepted. The file on disk is a different file,
because the 2026-10-11 repair (`8bf9271`) removed 7,702 repeated words from chapters 9–14 for real.
**The gate is right. The record is stale.**

## Why "just update the hash" is wrong, and also would not work

Two reasons, and the second is the one that matters practically:

1. It converts *"these bytes were approved"* into *"whatever is on disk is approved"* and destroys
   the only evidence that a reading happened.
2. **It also fails.** `tools/verify.py:118` requires the accepted record's hash to equal the
   `draft_sha256` of its coverage file — *"accepted content is not the reviewed content"*. The
   accepted bytes were, at acceptance time, byte-identical to a reviewed draft revision. Overwrite
   the accepted hash alone and you get a different red line, then a third one at `:150`.

So the honest fix has to restore the invariant **the accepted thing is the reviewed thing**, which
means the repaired bytes must first *become* a reviewed revision.

## What `apply_reaccept.py` does

For each of the seven chapters, in this order:

| # | Step | Why |
|---|---|---|
| 1 | The repaired bytes are cut as a new draft revision `R(n+1)` | the accepted artifact must exist and be readable |
| 2 | A dated per-chapter receipt is written, carrying **both** hashes | the old acceptance is superseded visibly, not erased |
| 3 | A new coverage record is created for that revision | `verify.py:118` couples acceptance to coverage |
| 4 | The draft ledger entry is appended | `verify.py:154` rejects undeclared drafts |
| 5 | **Only now** the accepted record is re-stamped — new `accepted_on`, new receipt | a new date is a new claim |
| 6 | `CHECKSUMS.sha256` is refreshed for the touched paths | nothing verifies it, so it must not be allowed to lie |

Nothing is deleted. The pre-repair bytes stay reachable forever:

```bash
git show 8bf9271^:chapters/Chapter_11_The_Sun.md
```

The five stale *generated* views (`README.md`, `HANDOFF.md`, `STATUS.md`,
`foundation/STATUS_PANEL.md`, `foundation/SERIAL_LOG.md`, `foundation/CANON_LEDGER.md`) are
regenerated by the repository's own renderers, in the order its `AGENTS.md` prescribes. That
sequence is mandatory: the manifest digest is stamped into every generated view, so a re-stamp
without a re-render is a `MIRROR: stale generated …` failure — which is what appeared, correctly,
on the first attempt.

## How to apply

```bash
git clone git@github.com:gm5206663-bit/supergirl-adrian-vale.git
cd supergirl-adrian-vale
git checkout -b reaccept/2026-10-30
python3 /path/to/apply_reaccept.py --dry-run   # read it first
python3 /path/to/apply_reaccept.py
python3 tools/render_codex.py
python3 tools/render_state.py
python3 tools/run_all.py                        # must print PROJECT CHECKS: PASS
git add -A && git commit -m "Re-accept chapters 9–15 after the 2026-10-11 repair (author ruling 2026-10-30)"
```

The script is idempotent in the useful direction: a chapter whose accepted hash already matches its
file is skipped, so a partial run can be re-run safely.

## What this deliberately does not touch

Chapters 9–14 sit below the 3,000-word floor their own headers claim — 2,569 / 2,729 / 1,333 /
2,256 / 2,933 words, measured 2026-10-13. **The padding was the length.** Re-accepting the repair
accepts the shorter chapter; restoring the length means writing prose, which is authoring, not
repair. That remains open on the author's desk, and this change makes it *more* visible rather than
less: the receipt for each chapter states the shortfall in plain text.
